# 12. UI design tournament

Build many very different versions of one page, judge them side by side, and merge
the best ideas. One agent iterating on one design gets stuck near its first draft.

**Copy-paste:**

```
Pick one page on my site that matters for money or sign-ups (landing, pricing, or
the top traffic page). Read its current version and analytics if I have them.

Build 8 to 12 fundamentally different versions of the page, each in its own git
worktree. Different layouts, hierarchy and offer framing, not colour swaps.

For each version, render desktop and mobile screenshots with the browser I already
have installed. Screenshot the 3 to 5 strongest competitor pages the same way.

Score every version against one rubric you write first: clarity of the offer in
5 seconds, path to the main action, trust signals, mobile usability, load weight.
Eliminate the weakest half. Combine the best ideas from the survivors into one
final version on a branch, and open a PR with the screenshots and score table.
Do not deploy.
```

**Notes**
- Write the rubric before you see the designs, or the judging bends to fit them.
- The PR with screenshots is the deliverable. You pick, the agent does not ship.

**Origin**
- From an AI assistant's answer to "how should I spend a large budget on my strongest
  model?" (November 2026). The ranking in that answer was its own guess.
- Limit: not yet run and measured by this repo. Open a PR with your result.
